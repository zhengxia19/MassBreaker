# 开发任务清单与依赖关系

**编号：** MB-TASK-005｜**状态：** 当前开发计划；按必要依赖安排实施。

## 1. 执行原则

- C++20 + SDL3 3.4.20 + GLES 3.0（Android）/GL 3.3（Windows）；只开发一条主线，不开展 Java/Rust/Vulkan 等备选研究。
- 沿“**配置与关卡先于物理 → 单球闭环 → +3 多球 → 完整 UI/存档 → 特色内容 → Android 发布**”顺序实施。
- 现有 30 关 `.tmj` 与 JSON 属于设计资产，不等于已有 C++ 游戏源码或实际可玩关卡；每项任务要以真实代码／运行效果验收。
- 低功耗调度、缓冲复用、增量维护和碰撞快速路径直接作为开发交付，不留到验收后再补做。
- 每个任务按改动范围选择验证；一个测试或运行记录可覆盖多个要求，不按用例编号重复搭建测试。资源/文档任务不强制提交 C++ 源码或重新构建；完整真机验收集中在发布候选，重大性能改动提前执行。

### 阶段里程碑

- M1 基础工程：T01–T05；双平台能启动并加载实际关卡。
- M2 可玩引擎：T06–T09；单球和道具多球规则形成真实闭环。
- M3 产品界面：T10（依赖 T08+T09）实现页面/交互；T11 在 T03 后可并行实现保存；两者就绪后接入真实存档，T12 完成正式资源及 **完整 UI 集成验收**。模拟 SaveResult 仅在真实实现尚未就绪时使用，不强制先做占位再返工。
- M4 内容：T13–T15；现有工具集成、参考关卡调优、30 关交付。T09/T13 就绪即可开展内容试玩，T15 的完整解锁/产品验收仍等待 T11/T12。
- M5 发行：T16–T17；真机正常回归和签名发行。


## 3. 每个任务必须遵守的实现约束

- 不为每块砖创建动态物理体；网格 96×160 独立于 Android 像素尺寸。
- 多球模拟单线程按稳定 ID 处理；同一时间组命中去重；B 的生成和拾取顺序遵循 [`12_CORE_ALGORITHMS.md`](12_CORE_ALGORITHMS.md)。
- 渲染砖块使用 60KiB `GL_RGBA8UI` 状态纹理；CPU 数据按格增量维护，有 dirty 的实际显示帧整图一次上传。不得提前开发复杂脏矩形优化器。
- 配置、输入、关卡、物理、UI/音效、存档必须可明确定位所属模块；不允许 UI callback 直接改砖格。
- 工具链只用于开发机；发行 APK 不打包 Python、Tiled 或调试生成器。

- [ ] 正常逻辑和失败逻辑可按给定条件复现，必要单测通过。
- [ ] 代码、规则参数、Tiled 源、运行时关卡、预览图无不一致；规范变更同步更新文档。

## 5. 明确不建立的工作项

已确定的节能设计随模块直接实现；不要求先编写低效版本再优化。没有 Java/C++/Rust 同题性能比较、独立大型物理引擎、ECS、GPU Compute、通用场景脚本系统、云端编辑平台、Vulkan、球球碰撞、长达数周的性能 PoC。遇到真实瓶颈时，仅针对已测出的瓶颈处理。已有工具不重写；未有重复编辑需求不建模板生成器。测试仅需固定输入/必要日志，不建通用录制回放平台；Windows 保留开发入口与构建验证，不增加桌面安装器、发行渠道或独立性能矩阵。
