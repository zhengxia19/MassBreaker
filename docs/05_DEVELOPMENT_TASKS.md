# 开发任务清单与依赖关系（V1.3.1）

**编号：** MB-TASK-005｜**状态：** 实施顺序冻结；需求和接口以 V1.3.1 项目文档为准。

## 1. 执行原则

- C++20 + SDL3 3.4.20 + GLES 3.0（Android）/GL 3.3（Windows）；只开发一条主线，不开展 Java/Rust/Vulkan 等备选研究。
- 沿“**配置与关卡先于物理 → 单球闭环 → +3 多球 → 完整 UI/存档 → 特色内容 → Android 发布**”顺序实施。
- 现有 30 关 `.tmj` 与 JSON 属于设计资产，不等于已有 C++ 游戏源码或实际可玩关卡；每项任务要以真实代码／运行效果验收。
- 每个任务包含必要的确定性单元测试或真机功能检查；性能在真实场景中记录，不建立脱离游戏的庞大技术验证阶段。

### 阶段里程碑

- M1 基础工程：T01–T05；双平台能启动并加载实际关卡。
- M2 可玩引擎：T06–T09；单球和道具多球规则形成真实闭环。
- M3 产品界面：T10 页面/交互阶段验收 → T11 真实保存 → T12 正式字体/声音/视觉及 **完整 UI 集成验收**；不能在 T10 提前标记全部 UI 功能通过。
- M4 内容：T13–T15；关卡编辑工具、三例调优、30 关交付。
- M5 发行：T16–T17；真机正常回归和签名发行。

**纠正 V1.1 的关键依赖错误：** 关卡加载 T03 必须在首关 T08 前完成；三例关卡 T14 不要求前三关都具有 B 砖（L001–L004 为单球关），增球验收明确在 L005 进行。

## 3. 每个任务必须遵守的实现约束

- 不为每块砖创建动态物理体；网格 96×160 独立于 Android 像素尺寸。
- 多球模拟单线程按稳定 ID 处理；同一时间组命中去重；B 的生成和拾取顺序遵循 [`12_CORE_ALGORITHMS.md`](12_CORE_ALGORITHMS.md)。
- 渲染砖块使用 60KiB `GL_RGBA8UI` 状态纹理；本帧有状态变化可整图一次上传。不得提前开发复杂脏矩形优化器。
- 配置、输入、关卡、物理、UI/音效、存档必须可明确定位所属模块；不允许 UI callback 直接改砖格。
- 工具链只用于开发机；发行 APK 不打包 Python、Tiled 或调试生成器。

- [ ] 正常逻辑和失败逻辑可按给定条件复现，必要单测通过。
- [ ] 代码、规则参数、Tiled 源、运行时关卡、预览图无不一致；规范变更同步更新文档。
- [ ] 日志和报错可定位，不隐式吞掉多球奖励，不以加速观看掩盖游戏过慢。

## 5. 明确不建立的工作项

没有 Java/C++/Rust 同题性能比较、独立大型物理引擎、ECS、GPU Compute、通用场景脚本系统、云端编辑平台、Vulkan、球球碰撞、长达数周的性能 PoC。遇到真实瓶颈时，仅针对已测出的瓶颈处理。

## 6. 设计缺陷的责任归属（V1.3.1 强制）

- **T04 前**：完成控制通道，验证没有 fixed tick 的 PAUSED 状态能立即处理 Resume/Retry；**主循环每 fixedTick 之后重新检查状态**，终态和 PLAYING→READY 转场立即清空累积时间、停止追赶；提交 LOOP-01..04 用例；T10 将控制接入真正的 UI 模态。
- **T07 前**：固定 `FramePacket.currentTick.hud` 唯一路径、11 个事件枚举及载荷（含 `PaddleHit`、`ItemCollected`）；T07 实现控制事件（0 tick 也可生成 SessionReset）与物理事件一次性 drain、帧快照、纹理单次上传；提交 FRAME-06/API-01。
- **T04/T10 前**：统一模态优先级，不允许确认框期间点击穿透到底层暂停或世界操作。
- **继续编辑任何关卡前／T13 前**：本包已修复 `export.py`，明确校验 `bricks` 图层自身的 `width=96, height=160`（不能只看地图尺寸或数据长度）；保留原 offset 修复与单测。项目集成运行 `unittest` 和 `validate.py --source`，异常尺寸不得覆盖既有 JSON。
