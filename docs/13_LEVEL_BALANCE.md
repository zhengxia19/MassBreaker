# 关卡数值与内容平衡设计

**编号：** MB-BAL-013

**证据边界：** 数量由当前 `.tmj` / `.json` 实际统计；**未做 C++/Android 实测，实际局时和过关率未知**。

## 1. 平衡目标

前四关使用较少目标砖训练单球操作；后续关卡通过 B 砖拾取逐步增加活跃球数，配合更复杂的布局。

原则：初始每关只有一球；无自动增球、无观看加速；只有 B 砖掉落 `+3`，由挡板拾取才能产生球；球会丢失，因此地图 B 的全部理论值不代表实际球数。前几关收敛可击目标量，后续通过增加密度、入口结构及 B 分布提升覆盖范围。

| L011–L015 | 两腔/嵌套结构反弹 | 2,200–3,000 | 8–12 |

这不是严格线性难度模型：难度还取决于墙体、通道、球的回弹周期、B 的可达性与玩家技术。任何规定局时／难度星级必须等到真实试玩之后才能填入验收记录。

## 4. 道具放置的关卡级规则

1. L001–L004 不存在 B；L005 引入 3 个 B，至少有一枚位于下缘外表面（当前资源的 B 均至少有一个空白四邻格）。
2. B 只能替换既有目标砖，不得填入墙、挡板控制区或空白裂缝；B 是可清除目标，破坏后生成一个可掉落道具，**不是立即生成 3 球**。
3. 同关 B 分布在不同 x 区段和纵深，避免仅靠通关末期才能获得全部奖励；因复杂墙体可能改变反弹概率，**“容易取得”仍须真人试玩确定**。
4. B 掉落物**穿过静态砖/墙、只在碰到挡板时生效**；无法接住时不补发。
5. 任何数字调整必须更新 `.tmj` → `.json` → 预览/清单，并同步本规范与任务验收记录；禁止只改截图或文档。

## 5. 最小关卡平衡验收流程（纳入正常开发）

**每关记录：** 关卡/资源标识、设备、完成结果、通关耗时和关键问题。总目标、HP 总量、B 数直接引用 manifest；首次 B 时刻、实际拾取数和峰值球数由调试计数自动采集，或在平衡诊断时补充，不要求人工逐项抄录。无 B 的关卡不填 B 时刻。每关至少通关一次；额外策略仅用于多入口、疑似卡球或路线失衡，已有有效试玩记录可跨任务复用。

- L001–L004：验证单球有明确的首轮有效击砖路线；如果持续处在反弹无进展状态，应调整入口及砖量，**不添加自动观看加速**。
- L005：必须真实触发并拾取至少 1 个 B，体验 4 球以上的过程。
- L006–L015：重点检查多球能否进入主要腔体、道具是否只有极低概率获得。
- L016–L030：检验大量球时碰撞精度、密集音效节流、复杂墙体可达性，以及全清难度。

**现有资源状态：** 30 个关卡均已通过 schema、Tiled 对照和“忽略可摧毁砖、仅按固定墙进行的保守通路检查”。这些检查不证明球一定能按真实反弹角度完成清关。完成实际游戏后才能将 `draft` 状态改为 `playtested`。

## 6. 后续调整边界

可根据试玩修改：特定关卡的砖量、HP、B 位置、入口宽度及墙体形状。不要在关卡间私自修改全局球速、半径、弹球上限或碰撞求解规则；全局调参必须在 [`gameplay.json`](../assets/config/gameplay.json) 统一调整并完整回归。
