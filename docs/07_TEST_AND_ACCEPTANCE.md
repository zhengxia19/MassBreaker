# 功能测试、关卡验收及发布质量门槛（V1.3.1）

**编号：** MB-QA-007｜**性质：** 与开发任务绑定的常规质量保障，不单设大型技术研究。

## 1. 分层验收范围

| 层次 | 已交付证据 | 开发期间还需交付 |
|---|---|---|
| 文档与资源静态 | 30 Tiled/JSON 对照、schema、marker、固定墙可达性基本检查 | Tiled 实际 GUI 打开/保存与每次关卡修订后的工具回归 |
| 核心 C++ 算法 | 已冻结行为接口和 ALG 测试输入/预期 | 真实 C++ 单元测试、异常路径、确定性结果 |
| 可玩游戏 | 仅有线框和关卡设计草案 | Windows/Android 运行、L001/L005 实际游戏闭环 |
| 正式内容 | 30 个可编辑关卡草案 | 每关真实人工通关、道具拾取、记录必要调整 |
| Android 发布 | 构建方案文档 | 真机安装、前后台、性能、签名、更新与发行资料 |

## 2. 核心算法验收

单测优先覆盖 [`12_CORE_ALGORITHMS.md §11`](12_CORE_ALGORITHMS.md) 的 **ALG-01 至 ALG-14**，以及 §12/§13 的 **CTRL-01..05 / FRAME-01..06 / LOOP-01..04 / API-01..02**。特别是：高速穿过细砖、擦过圆角但未碰撞、双砖同时间接触、两球同一物理步毁同一块砖、B 拾取时最后球掉出、最后目标与最后球同 tick 消失、1024 上限的积分补偿。

每个关键用例需给定精确起点、速度、球 ID、砖格和预期 HP、积分、球数，不使用难以复现的视觉观察代替测试。需要时引入一个固定 seed，记录 `tick/id/position/HP/score` 最小事件日志。

## 3. UI 与交互验收

八种页面与状态按 [`10_UI_UX_DESIGN.md`](10_UI_UX_DESIGN.md) 及 [`14_VISUAL_DESIGN_AND_FEEDBACK.md`](14_VISUAL_DESIGN_AND_FEEDBACK.md) **分三阶段验收**：T10 页面/交互（可占位字体及注入保存结果）、T11 真实存档与保存成功门槛、T12 正式字体/音效/视觉与 UI 整体集成。**不得在 T10 时提前声称完整 UI 产品验收通过。**需检查 360×640、360×800 和至少一台实际 Android 高 DPI 屏幕。主要检查安全区、挡板移动时指针捕获、轻点才发球、多指不劫持、系统返回打开暂停、后台恢复无跳帧。

保存失败必须明确提示；重启后已解锁与最佳成绩持久化。L030 成功页不显示无效的“下一关”。

## 4. 关卡验收（正常内容制作流程）

- 30 关均从真实资源 JSON 加载，实际画面与渲染预览的砖块/墙位置一致。
- 所有关卡**至少人工通关一次**，复杂关（L013、L023、L028、L029、L030）至少再采用另一操作策略试玩。
- L001–L004 验证单球可击中主要砖阵，无长时间无法触及的目标；L005 能实际击破 B 并接到 +3；后续关卡存在可获得的多球过程。
- 一旦关卡数据修改，运行导出、全部校验和截图同步，不能把旧预览当成新版验收。
- 记录：关卡、版本、机型、完成结果、总耗时、首次 B 接取时间、拾取道具数、峰值球数、关键问题；目前这些**实际值未知**。

**结构检查与可玩性严格区分：** `geometry.py` 假设目标砖最终可移除，只证明没有明显的固定墙封闭，不能证明特定入射角、过关时长或球永不被困。

## 5. 性能与设备检查

- 目标 60 FPS，记录典型关卡和多球场景的 P50/P95 帧时间，以及真实设备型号、系统、分辨率、活动球与砖数；没有任何已完成的真实帧率证据。
- 使用实际 L016 / L028 / L030 场景作为常规回归；额外一次 10,000 格 + 300 球可作为可选工程压力场景，而不必形成独立研究项目。
- 保证不会因设备性能慢而悄悄删除球、跳过碰撞或改变玩法时钟。若明显过载，记录且修复具体热点。
- 检查横竖屏约束、后台/锁屏、GL 上下文恢复、音量设置、进度存储、连续重开内存稳定、APK 无不必要权限。

## 6. 发布质量门槛

| 级别 | 典型问题 | 允许发布？ |
|---|---|---|
| Blocker | 无法打开/关卡不可完成/数据损坏/系统性穿砖 | 否 |
| High | 道具不触发、错误扣命、严重持续掉帧、暂停失效 | 否 |
| Medium | 少量动效错位、偶发非阻塞音效错误 | 修复或明确记录后评估 |
| Low | 非必要装饰瑕疵 | 允许登记后改进 |

最终产物：Windows 构建记录、Android debug APK 与 release APK/AAB、30 关人工试玩记录、关键单测结果、资源授权清单、真实机型/帧时间记录、Git commit/签名与版本记录。设计文档和地图通过静态测试，**不等于已经完成这些发布条件**。

## 7. V1.3.1 缺陷回归门槛

| 风险 | 可复现测试 | 所属任务 |
|---|---|---|
| 暂停无法恢复 | 暂停中执行 20 次渲染且 0 fixed tick 后点 Resume，立即恢复，首个 tick 使用新时钟 | T04 / T10 |
| Retry 必须等待 fixed tick | 暂停 → 打开确认弹窗 → 确认重试；当帧重置关卡/砖格/快照，无物理补算 | T04 / T10 |
| 输入透传 | 模态打开时点底层暂停和拖动区域；`Back` 仅取消模态，旧 finger 抬起不发球 | T04 / T10 |
| 多 tick 事件漏掉/重复 | 1 次显示帧包含 3 个物理步，UI 顺序收到所有重要事件 1 次，砖纹理最多上传一次 | T07 |
| 旧球/道具误插值 | 增球和失球同帧发生、重开和 GL 恢复；只按相邻物理 tick 的稳定 ID 插值 | T07 |
| 微砖画面看起来像连续色块 | 实际 L003、L028 真机截图和真实运行时 JSON 结构对齐，每个可见微格与状态纹理一致 | T07 / T12 |
| 高密度特效遮挡 | 多球、连击时球芯可见，粒子/音频可限流但模拟计数不可降低 | T12 |
| Tiled offset 静默丢失 | 单测 `bricks/markers` 的 `offsetx=8`/`offsety=8` 必须抛出命名错误，CLI 非零退出、不覆盖原输出 | T13 前 |
| Tiled 砖层自身宽高错误被静默忽略 | 修改 `bricks.width/height` 为 `48×320`、`160×96` 或 `96×159`，保持 data 长度不变，导出必须拒绝；现有 JSON 不被覆盖 | **继续编辑关卡前** |
| 终态后继续运行固定步 | 5 dt 追赶第 2 tick 进入 WON/LOST/READY；实际调用仅 2 次且清空余时；已发生终态事件仍被交付 | T04/T06/T08 |
| UI HUD 路径与事件枚举冲突 | 编译校验 `frame.currentTick.hud` 唯一路径、PaddleHit/ItemCollected 与 11 事件枚举一致；零 tick Retry 本帧交付 SessionReset | T07/T10 |
| UI 验收的未来依赖 | T10 仅做页面交互与模拟 SaveResult；T11 真实存档；T12 在 T11 完成后做正式资源与全 UI 联验 | T10/T11/T12 |

`python -m unittest discover -s tools/level-export -p "test_*.py" -v` 是设计工具的真实自动测试入口（V1.3.1 共 12 项）；C++ CTRL/FRAME 用例必须在对应任务实现后才有运行结果。所有视觉 PNG 属于设计稿，不应伪称 Android 真机通过。

## 8. V1.3.1 版本的证据范围与不允许跳过的检查

- Python 导出器必须实际运行 12 项单元测试；`test_09` 验证等长异常尺寸，`test_10` 验证类型缺失，`test_11` 验证 CLI 失败不覆盖旧 JSON。设计包里的 30 关应继续通过 `validate.py --source` 和 `geometry.py`。
- C++ 主循环、帧数据、游戏事件的 `LOOP/FRAME/API` 用例**目前只是规格**，必须在 T04/T06/T07/T10 按职责编码和执行；文档文字正确不能当作测试通过。
- T10 的 `SaveResult` 测试注入不得用于生产替代真实保存。T11 必须实测真实存档，T12 必须完成整个页面和美术、字体、音效联合验收。
