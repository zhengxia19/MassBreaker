# 产品需求规格（PRD）

**文档编号** MB-PRD-001｜**状态** 产品范围与游戏规则接口已冻结

## 1. 产品主张

Mass Breaker 是一款 Android 竖屏休闲打砖块游戏。玩家通过挡板维持弹球运动，击毁高密度微型砖阵，在破口、隔板和腔体内形成持续反射；拾取道具后活跃弹球增多，从局部突破发展到较大范围清除。关卡的辨识度与反弹体验是主要卖点。

## 2. 核心使用流程

首次打开→简短操作提示→第一关→附着单球准备→轻点控制区发球→拖动挡板→碰撞击砖/掉落道具→全部目标砖块清除后结算→下一关。失败时可重试或返回选关。

菜单流程：启动界面→主菜单（继续／选关／设置）→关卡页面→游玩；游戏内支持暂停、重开、退出到选关。首次进入时无需注册和网络授权。

## 3. 功能需求

| ID | 优先级 | 功能 | 完成条件 |
|---|---|---|---|
| FR-01 | P0 | 竖屏单指控制挡板 | 单指横向拖动挡板；READY 状态轻点控制区发球；不必直接按住挡板 |
| FR-02 | P0 | 发球与弹球运动 | 开局球附着挡板；点击开始；按固定步长反弹 |
| FR-03 | P0 | 微型砖块碰撞 | 命中扣 HP；归零清除；快速球不穿砖 |
| FR-04 | P0 | 静态结构/通道 | 地图可配置不可破坏墙与缺口，不算清关目标 |
| FR-05 | P0 | 多球 | 道具触发后增加弹球，路径独立；掉落逐球回收 |
| FR-06 | P0 | 道具 | 至少 +3；出现、下落、接住、触发、提示完整 |
| FR-07 | P0 | 生命与失败 | 全部弹球丢失扣生命；生命用尽进入失败页 |
| FR-08 | P0 | 关卡完成 | 剩余目标砖为零立即判胜，进入结算页 |
| FR-09 | P1 | 计分与星级 | 保存最佳得分、最佳星级，规则可解释 |
| FR-10 | P1 | 关卡选择/解锁 | 已通关关卡可重玩，下一关逐级解锁 |
| FR-11 | P1 | 暂停与后台恢复 | 音频、物理同步暂停，返回恢复不跳帧 |
| FR-12 | P1 | 声音/视觉反馈 | 砖块击碎、增球、失球、结算有反馈，支持静音 |
| FR-13 | P1 | 本地存档 | 退出重启后进度、最佳成绩与设置完整 |
| FR-14 | P1 | 30 个正式关卡 | 6 个章节，每章 5 关；人工试玩确认 |
| FR-15 | P1 | Android 发布包 | debug APK、签名 release APK/AAB 可安装 |

P0 为最先必须具备的游戏闭环；P1 为 V1 发布必须具备的完整产品能力，P1 不代表可省略。

## 4. 非功能需求

| ID | 项目 | 约束 |
|---|---|---|
| NFR-01 | 平台 | Android 竖屏优先，首版 arm64；Windows 桌面预览 |
| NFR-02 | 离线 | 游戏启动、游玩、关卡读取、存档均无需网络 |
| NFR-03 | 性能 | 目标 60 FPS；记录典型场景 P95 帧时间；不进行播放加速或偷偷丢弃球 |
| NFR-04 | 容量 | 固定 96×160 网格（15,360 格位置）；实际目标砖 320–5,200；球池容量 1024，关卡理论峰值不等于容量 |
| NFR-05 | 数据 | 写存档失败不能破坏已有进度；schemaVersion 明确 |
| NFR-06 | 适配 | 常用 Android 竖屏尺寸、刘海/手势安全区、前后台切换 |
| NFR-07 | 可维护 | 游戏规则与图形/Android 平台调用解耦；关卡无需修改 C++ 源码 |
| NFR-08 | 安装 | 不申请无关权限；V1 不需要网络权限、用户账户或外部存储权限 |
| NFR-09 | 低功耗 | 游戏显示目标 60 FPS；静态 READY/菜单/暂停/结算按需更新；后台停止游戏计算和图形提交，不忙等 |
| NFR-10 | 持续运行 | 稳态关键路径零堆分配，有界视觉预算；首次可玩起采集轻量性能及可用功耗记录；发布验收检查持续运行，精确能耗按设备能力独立给出结论 |

球池硬上限属于公开的游戏规则限制，不随设备负载动态变化。超限补偿、同帧事件优先级、发球角度等权威规格见 [12_CORE_ALGORITHMS.md](12_CORE_ALGORITHMS.md) 和 [gameplay.json](../assets/config/gameplay.json)。

## 5. 界面定义

**详细交互规格在 [10_UI_UX_DESIGN.md](10_UI_UX_DESIGN.md)，完整微砖与 UI 视觉规格在 [14_VISUAL_DESIGN_AND_FEEDBACK.md](14_VISUAL_DESIGN_AND_FEEDBACK.md)**。包含 8 张细化设计图、两张基于真实地图的游戏画面示意、适配与输入优先级。

| 页面 | 内容 | 交互 |
|---|---|---|
| 启动/首页 | 游戏标识、继续、选关、设置 | 继续进入最近解锁关卡 |
| 选关 | 章节、关卡序号、星级、解锁状态 | 选择已解锁关卡 |
| 游戏场景 | 砖阵、球、挡板、道具、生命、分数、暂停按钮 | 手指控制挡板、点击发球 |
| 暂停 | 继续、重新开始、退出 | 暂停时物理与音效停止 |

| 失败 | 本次分数、重试、选关 | 不自动清除已经解锁的进度 |
| 设置 | 背景音乐、音效、震动可选、版权信息 | 本地保存并即时生效 |

## 6. 交互与易用性

- 玩家手指可在游戏下部触控控制区拖动挡板，触摸点与挡板之间保持固定偏移，避免手指直接遮挡球。
- 点击暂停需要处于屏幕安全区域，不与挡板控制冲突；Android 系统返回等价于暂停或返回上一级。
- 一关开始时球固定于挡板上方，轻点控制区可发球；失去全部弹球且尚有生命时重复此流程。
- 动效以辨识球与破口为优先，粒子、光晕不能覆盖主球运动和通道入口。
- 声音反馈有冷却/聚合规则，防止数百球碰撞时音频过载。
- 暂停面板的继续、确认后的重试必须在显示帧控制通道立即生效，不等待 fixed tick；模态层取消旧触控捕获并阻止底层拖动或发球。

## 7. 关卡内容要求

**30 份 Tiled 可编辑源、运行时 JSON、布局预览和逐关规格见 [11_LEVEL_DESIGN.md](11_LEVEL_DESIGN.md)**。它们是设计草案，尚未完成正式游戏内试玩。

正式内容 30 关：并非 30 个随机排列，而是 30 个经过命名、编辑、测试并有明确设计意图的布局。前三关直接围绕黄色中央通道、棕红分叉和紫色双腔体三种结构构建，后续逐步引入更多入口、复杂腔体和增球节奏。

## 8. 发布排除项

明确不做：加速观看、多球互撞、实时多人、云同步、排行榜、关卡分享服务器、广告/内购、动态障碍、完整内置编辑器、自动生成所有关卡、自研账户体系。未来版本需要独立需求变更。

## 9. 产品验收

用户无需技术背景即可在手机上完成首次进入、开球、控制、获得增球、赢一关、解锁下一关、关闭并重新打开游戏且保留进度。任何 V1 功能缺失，均不能认定产品已完成。

实施任务见 [05_DEVELOPMENT_TASKS.md](05_DEVELOPMENT_TASKS.md)，算法与数据契约见 [12_CORE_ALGORITHMS.md](12_CORE_ALGORITHMS.md)，完整验收门槛见 [07_TEST_AND_ACCEPTANCE.md](07_TEST_AND_ACCEPTANCE.md)。
